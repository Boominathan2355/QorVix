# Test fixtures

Two kinds of file live here, and the distinction matters:

- **Probes** — inputs. Committed so that every gate runs on the same bytes on every machine.
- **References** — expected outputs, captured **from an independent implementation** by a
  `scripts/capture_*.py` harness and committed alongside. A reference produced by qorvix itself
  would make its gate self-referential and prove nothing, so every one of these names its source in
  its own header.

| file | what it is | provenance |
|---|---|---|
| `audio_probe.wav` | 2 s, 16 kHz mono PCM16 | synthetic; generated by `scripts/make_audio_probe.py` |
| `speech_probe.wav` | 11 s, 16 kHz mono PCM16 | John F. Kennedy, inaugural address, 1961 — a US federal government work and therefore public domain. Distributed with whisper.cpp as `samples/jfk.wav`. |
| `vision_probe.png` | small RGB PNG | synthetic |
| `audio_reference_whisper_tiny.txt` | log-mel filter bank, waveform checksum, frames | transformers `WhisperFeatureExtractor` |
| `whisper_reference_tiny.txt` | encoder states, one step's logits, greedy transcript | transformers `WhisperForConditionalGeneration`, fp32 |
| `vision_reference_clip_vit_l14_336.txt` | preprocessed pixels + patch hidden states | transformers `CLIPVisionModel`, fp32 |
| `embed_reference_*.txt` | token ids + pooled vectors | sentence-transformers |
| `sd_reference_tiny.txt` | timesteps, prompt ids, conditioning, one UNet step, the sampled latent and the decode | diffusers `StableDiffusionPipeline` + `DDIMScheduler`, fp32 |

**Why the diffusion fixture carries its own starting latent.** Every other reference here is
compared against an input that is also committed. A diffusion sample starts from random noise, and
qorvix's noise is deliberately its own (see `image/rng.hpp`) — reproducing `torch.randn` would tie
this runtime's output to another project's internals and still only agree on CPU. So the fixture
writes the latent diffusers started from, both runtimes denoise the same tensor, and no random
number generator is part of what is being compared. It is captured at 32x32 on a tiny test
checkpoint precisely because the whole latent has to fit in a text file.

**Why the speech probe is real speech and the audio probe is not.** The front-end gate
(`audio-check`) compares numbers, and a tone sweep exercises the filter bank harder than speech
does. The model gate (`whisper-check`) compares a *transcript*, and on synthetic audio Whisper
hallucinates — deterministically, so a parity check would still pass, but the fixture would then
assert that two implementations agree on nonsense. Real speech makes the same tier assert that the
pipeline transcribes, which is the claim anyone reading the gate output will take from it.

Regenerate a reference rather than hand-editing it; each capture script prints the exact command in
its docstring, and `models/README.md` lists them per phase.
